# نقشه راه Java Core، از صفر تا سطح محکم

برای امیررضا قادری.

هدف این مسیر Java 21 LTS است: خود زبان و کتابخانه استاندارد، از اولین `main` تا جایی که یک برنامه کوچک را خودت طراحی کنی، بنویسی، اجرا کنی و خطایش را بخوانی. پیش‌فرض این سند صفر است. اگر قبلاً با زبان دیگری کار کرده باشی، فازها را رد نکن؛ فقط تمرین را کمی تندتر بنویس.

## Java Core چیست و چیست نیست

Java Core یعنی خود زبان جاوا و آن بخش از کتابخانه استاندارد که بدون هیچ فریم‌ورکی هم لازم است:

- نحو زبان: نوع، متغیر، عملگر، شرط، حلقه، متد، آرایه
- برنامه‌نویسی شیءگرا: class، شیء، وراثت، interface، چندریختی
- exception، generics و Collections
- فایل با I/O و NIO.2
- lambda، Stream و Optional
- مبانی concurrency
- تصویری ساده و درست از JVM، در حدی که بدانی برنامه چطور اجرا می‌شود

این مسیر عمداً این‌ها را درس نمی‌دهد: Spring، هر فریم‌ورک وب، Android، دیتابیس، و ساخت API. Maven و Gradle را هم وارد نمی‌کنیم. تا پایان همین سند با `javac` و `java` کار می‌کنیم تا معلوم باشد پشت ادیتور چه اتفاقی می‌افتد.

## روش مطالعه

هر بار فقط یک فاز. درس کوتاه است، بعد بلافاصله کد. فاز بعدی شروع نمی‌شود تا تمرین‌های فاز فعلی را خودت اجرا کرده باشی و جمله «برای فاز بعد آماده‌ای وقتی» را صادقانه برآورده کرده باشی.

اگر گیر کردی، راه‌حل کامل نخواه. بگو روی کدام خط مانده‌ای و متن خطا چیست. خطا بخشی از درس است، نه علامت توقف.

کد را در پوشه‌ای به نام `java-core` نگه دار. هر فاز یک زیرپوشه دارد، مثل `phase-01`. هر برنامه یک فایل `.java` جداست. نام فایل و نام class یکی است.

نسخه را همان اول قفل کن: **JDK 21**. اگر `java -version` عدد 21 را نشان نداد، قبل از هر تمرین دیگری همان را درست می‌کنیم.

## [فاز ۱ — محیط و اولین برنامه](core/01-environment.md)

**هدف:** JDK 21 را راه بیندازی و یک برنامه را خودت کامپایل و اجرا کنی.

**موضوع‌ها**

- [ ] نصب JDK 21 و دیدن نسخه با `java -version` و `javac -version`
- [ ] فایل متنی `.java`؛ نام فایل برابر نام class
- [ ] قالب `main` را عین همین شکل بنویس. معنی `static` را فاز ۵ باز می‌کنیم
- [ ] `System.out.println` برای چاپ یک خط
- [ ] `javac` فایل `.class` می‌سازد؛ `java` همان را اجرا می‌کند
- [ ] کامنت `//` و پیدا کردن شماره خط در پیام خطای کامپایلر

قالب جلسه اول، که خودت تایپ می‌کنی:

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("...");
    }
}
```

از همان پوشه فایل:

```bash
javac Hello.java
java Hello
```

**تمرین**

1. **سلام.** `Hello.java` را طوری بنویس که دقیقاً چاپ کند: `سلام، امیررضا`. کامپایل و اجرا با دستورهای بالا.
2. **سه خط.** برنامه `AboutMe` در سه `println` جدا این‌ها را چاپ کند: نام تو، یک عدد که خودت انتخاب می‌کنی، و یک جمله که بگوید این اولین برنامه جاوای توست.
3. **خطای عمدی.** از برنامه اول یک `;` را بردار. `javac` را دوباره بزن، شماره خط را در پیام پیدا کن، سمیکالن را برگردان و اجرای سالم بگیر.

**برای فاز بعد آماده‌ای وقتی** بدون جزوه یک class با `main` می‌سازی، `javac` و `java` را درست صدا می‌زنی، و اگر سمیکالن جا مانده باشد از روی پیام کامپایلر همان خط را نشان می‌دهی.

## [فاز ۲ — نوع، متغیر و عملگر](core/02-types-operators.md)

**هدف:** داده را در متغیر نگه داری، با آن محاسبه کنی، و از کاربر ورودی بگیری.

**موضوع‌ها**

- [ ] نوع‌های `int`، `long`، `double`، `boolean`، `char`
- [ ] نام‌گذاری متغیر: حرف کوچک در شروع، مثل `birthYear`
- [ ] عملگرهای `+ - * / %` و فرق تقسیم صحیح با تقسیم اعشاری
- [ ] تبدیل نوع وقتی لازم است، مثل `(double) a / b`
- [ ] `String` برای متن؛ چسباندن با `+`
- [ ] مقایسه رشته با `equals`، نه با `==`
- [ ] `import java.util.Scanner;` برای ورودی. کلاس‌های `java.lang` مثل `String` و `System` را import نمی‌کنی
- [ ] text block برای یک متن چندخطی، با `"""`

**مراقب این باگ باش:** `1 / 2` در `int` می‌شود `0`. برای میانگین نمره از `double` استفاده کن.

**تمرین**

1. **دما.** برنامه `Celsius` یک عدد بگیرد (درجه سلسیوس) و فارنهایت را چاپ کند: سلسیوس × ۹ ÷ ۵ + ۳۲. تقسیم باید اعشاری باشد. اگر هر دو طرف تقسیم `int` باشند، جاوا حاصل را به سمت صفر قطع می‌کند.
2. **مستطیل.** طول و عرض را بخواند و محیط و مساحت را در دو خط چاپ کند. اگر یکی از ضلع‌ها صفر یا منفی بود، به‌جای محاسبه بنویسد: `ضلع نامعتبر است`.
3. **چهار عمل.** دو `int` بگیرد و جمع، تفریق، ضرب، تقسیم صحیح و باقی‌مانده را چاپ کند. اگر عدد دوم صفر بود، تقسیم و باقی‌مانده را حساب نکند و بنویسد: `تقسیم بر صفر ممکن نیست`.
4. **منوی متنی.** با یک text block یک منوی سه خطی چاپ کند (جمع، تفریق، خروج). بعد یک `String` از کاربر بگیرد. اگر با `equals` برابر `خروج` بود بنویسد `خداحافظ`، وگرنه `ادامه`. کار خود منو مال فاز ۳ است.

**برای فاز بعد آماده‌ای وقتی** برای یک محاسبه کوچک نوع مناسب را انتخاب می‌کنی، ورودی عددی می‌گیری، و دو رشته را با `equals` مقایسه می‌کنی نه با `==`.

## [فاز ۳ — شرط و حلقه](core/03-condition-loop.md)

**هدف:** برنامه بر اساس شرط راهش را عوض کند و کار تکراری را با حلقه انجام دهد.

**موضوع‌ها**

- [ ] `if`، `else if`، `else`
- [ ] `switch` کلاسیک، و `switch` با فلش که از Java 14 استاندارد است و به case بعدی نشت نمی‌کند:

```java
String label = switch (choice) {
    case 1 -> "جمع";
    case 2 -> "تفریق";
    default -> "نامشخص";
};
```

- [ ] `for`، `while`، `do-while`
- [ ] `break` برای خروج از حلقه، `continue` برای پرش به دور بعد
- [ ] شرط پایان حلقه را قبل از اجرا با یک جمله فارسی بنویس تا حلقه بی‌نهایت نسازی

**تمرین**

1. **جدول ضرب.** یک عدد از ۱ تا ۱۰ بگیرد و حاصل‌ضرب آن در ۱ تا ۱۰ را چاپ کند. اگر عدد بیرون این بازه بود، یک جمله خطا چاپ کند و تمام شود.
2. **FizzBuzz.** اعداد ۱ تا ۵۰ را چاپ کند. مضرب ۳: `Fizz`. مضرب ۵: `Buzz`. مضرب هر دو: `FizzBuzz`.
3. **حدس عدد.** برنامه یک عدد بین ۱ و ۵۰ را در کد ثابت نگه دارد. کاربر با `while` حدس بزند. بعد از هر حدس بگو `بزرگ‌تر`، `کوچک‌تر` یا `درست`. بیشتر از ۸ حدس را با یک پیام تمام کن.
4. **ماشین‌حساب منویی.** منوی فاز ۲ را زنده کن. با `switch` فلش‌دار: ۱ جمع، ۲ تفریق، ۳ خروج. تا وقتی کاربر ۳ را نزده، منو تکرار شود.

**برای فاز بعد آماده‌ای وقتی** برای یک کار، خودت تصمیم می‌گیری `if` کافی است یا حلقه لازم است، و می‌توانی بگویی حلقه کی تمام می‌شود.

## [فاز ۴ — متد و آرایه](core/04-method-array.md)

**هدف:** کار را به متدهای کوچک بشکنی و چند مقدار هم‌نوع را در آرایه نگه داری.

**موضوع‌ها**

- [ ] تعریف متد `static` با پارامتر و `return`
- [ ] `void` وقتی خروجی نداری
- [ ] overloading: چند متد با یک نام و پارامتر متفاوت
- [ ] آرایه `int[]`، طول با `length`، مقداردهی اولیه
- [ ] پیمایش با `for` معمولی و با `for (int n : scores)`
- [ ] متد، کپی مقدار می‌گیرد؛ آرایه را که به متد می‌دهی، متد همان محتویات را می‌بیند

تا این فاز کد هنوز داخل همان class برنامه است و متدها `static` هستند. شیء از فاز ۵ شروع می‌شود.

**تمرین**

1. **سه متد.** `isEven(int n)`، `max(int a, int b)` و `average(int a, int b, int c)` را بنویس. `main` فقط آن‌ها را صدا بزند و نتیجه را چاپ کند. میانگین باید `double` باشد.
2. **نمره‌ها.** یک `int[]` با حداقل ۵ نمره بساز. متدهای میانگین، کمینه و بیشینه را روی کل آرایه بنویس و از `main` صدا بزن. اگر نام `average` را برای آرایه هم می‌خواهی، این همان overloading است. اگر آرایه خالی بود یک جمله چاپ کن و برگرد، نه اینکه برنامه سقوط کند.
3. **برعکس.** `reverse` یک `int[]` بگیرد و یک آرایه جدید برعکس برگرداند. آرایه ورودی نباید عوض شود. قبل و بعد را چاپ کن تا این را نشان بدهی.
4. **مساحت با overload.** دو متد `area`: یکی فقط ضلع مربع را بگیرد، یکی طول و عرض مستطیل را. هر دو را از `main` صدا بزن.

**برای فاز بعد آماده‌ای وقتی** یک محاسبه را از `main` بیرون می‌کشی، ورودی و خروجی متد را خودت انتخاب می‌کنی، و روی یک آرایه میانگین و بیشینه را با متد خودت حساب می‌کنی.

## [فاز ۵ — کلاس و شیء](core/05-class-object.md)

**هدف:** یک مفهوم واقعی را با class مدل کنی و وضعیت هر شیء را جدا و محافظت‌شده نگه داری.

**موضوع‌ها**

- [ ] class، فیلد، شیء، `new`
- [ ] سازنده (constructor) و کلمه `this`
- [ ] encapsulation: فیلد `private`، دسترسی از طریق متد
- [ ] فرق متد instance با متد `static`
- [ ] فیلد `static` که بین همه شیءهای آن class مشترک است
- [ ] `toString` برای چاپ خوانا
- [ ] package و اجرا از پوشه بالاتر
- [ ] سطح دسترسی `public` و `private`. `protected` را فاز ۶، کنار وراثت، می‌بینیم

دو شیء یعنی دو وضعیت جدا. اگر `a` را عوض کردی و `b` هم عوض شد، معمولاً اشتباهاً هر دو را به یک شیء وصل کرده‌ای، یا فیلد را `static` گذاشته‌ای.

**تمرین**

1. **شمارنده.** class `Counter` با `increment` و `getValue`. در `main` دو `Counter` بساز. یکی را سه بار زیاد کن. چاپ کن که دومی هنوز صفر است.
2. **حساب بانکی.** class `BankAccount` در package به نام `bank`. خط اول فایل باید `package bank;` باشد. نام صاحب حساب و موجودی `private`، متد `deposit` و `withdraw`. برداشت بیشتر از موجودی نباید موجودی را منفی کند؛ همان موقع بنویسد `موجودی کافی نیست`. `main` در همان کلاس یک واریز، یک برداشت موفق، و یک برداشت بیشتر از موجودی را نشان بدهد. از پوشه والد این‌طور اجرا کن:

```bash
javac -d . bank/BankAccount.java
java bank.BankAccount
```

3. **کتاب.** class `Book` با عنوان، نویسنده و سال، فقط از راه سازنده پر شود، و `toString` یک خط فارسی قابل خواندن برگرداند. سه کتاب بساز و چاپ کن.
4. **شمارش حساب‌ها.** به `BankAccount` یک فیلد `static` اضافه کن که تعداد حساب‌های ساخته‌شده را نگه دارد. سه حساب بساز و نشان بده این عدد برای همه یکی است، در حالی که موجودی هر حساب جداست.

**برای فاز بعد آماده‌ای وقتی** یک class با فیلد `private`، سازنده و متد می‌نویسی، دو شیء جدا می‌سازی، و می‌توانی توضیح بدهی کدام داده مال شیء است و کدام `static` است.

## [فاز ۶ — وراثت، interface و چندریختی](core/06-inheritance-interface.md)

**هدف:** رفتار مشترک را یک‌جا تعریف کنی و از طریق نوع والد یا interface با شیءهای مختلف یک‌جور کار کنی.

**موضوع‌ها**

- [ ] `extends`، `super`، و `@Override`
- [ ] abstract class وقتی زیرکلاس‌ها وضعیت مشترک دارند
- [ ] interface وقتی فقط یک قابلیت مشترک است، مثل قابل پرداخت بودن
- [ ] چندریختی (polymorphism): متغیر از نوع والد، شیء از نوع فرزند
- [ ] `protected` برای عضوی که فرزند لازم دارد و بیرون کلاس نه
- [ ] `enum` برای مجموعه ثابت وضعیت‌ها
- [ ] `record` برای داده‌ای که هویتش همان فیلدهایش است
- [ ] `instanceof` با الگو، از Java 16: `if (shape instanceof Circle c)`
- [ ] آشنایی با sealed class: محدود کردن اینکه چه classهایی حق `extends` دارند. در checkpoint الزامی نیست

قانون انتخاب، همین یک خط: وضعیت و کد مشترک می‌خواهی، abstract class. فقط قرارداد یک رفتار را می‌خواهی، interface.

اگر چند class را `public` کنی، هر کدام فایل جدا به همان نام می‌خواهد. ساده‌ترین کار در این فاز: فقط کلاسی که `main` دارد `public` باشد.

**تمرین**

1. **شکل‌ها.** abstract class `Shape` با متد abstract `area`. دو فرزند `Circle` و `Rectangle`. یک آرایه `Shape[]` بساز، هر دو نوع را داخلش بگذار، و در یک حلقه مساحت را چاپ کن.
2. **قابل پرداخت.** interface `Payable` با متد `int pay()`. دو class جدا (مثلاً `Salary` و `Invoice`) آن را پیاده کنند. در یک `Payable[]` هر دو را صدا بزن و جمع پرداخت را چاپ کن.
3. **وضعیت سفارش.** `enum OrderStatus` با `PENDING`، `PAID`، `SHIPPED`. یک متد با `switch` فلش‌دار برای هر وضعیت یک جمله فارسی برگرداند. هر سه مقدار را از `main` چاپ کن.
4. **نقطه.** `record Point(int x, int y)` بنویس و متد `distance` که فاصله اقلیدسی تا یک `Point` دیگر را به‌صورت `double` برگرداند. از `Math.sqrt` استفاده کن. دو نقطه بساز و فاصله را چاپ کن.

**برای فاز بعد آماده‌ای وقتی** یک interface یا abstract class با دو پیاده‌سازی داری و متد را از روی نوع والد صدا می‌زنی، بدون اینکه در `main` به نوع واقعی `if` بزنی.

## [فاز ۷ — Exception و Generics](core/07-exception-generics.md)

**هدف:** خطای قابل‌پیش‌بینی را مدیریت کنی و یک class یا متد را نسبت به نوع، عمومی بنویسی.

**موضوع‌ها**

- [ ] exception یعنی قطع شدن جریان عادی با یک شیء خطا
- [ ] unchecked مثل `IllegalArgumentException` و `InputMismatchException` که زیر `RuntimeException` هستند. checked زیر `Exception` است ولی زیر `RuntimeException` نیست و باید `catch` یا `throws` شود
- [ ] `try` / `catch` / `finally`
- [ ] `throw` برای پرتاب، `throws` برای اعلام
- [ ] یک exception اختصاصی با پیام فارسی روشن
- [ ] try-with-resources را اینجا فقط بشناس. بستن فایل با آن مال فاز ۱۰ است. `Scanner` وصل به `System.in` را نبند؛ ورودی استاندارد بسته می‌شود
- [ ] کلاس Generic مثل `Box<T>`، و متد Generic
- [ ] محدودیت `T extends Number` در حد یک مثال
- [ ] علامت `?` را فقط بلد باش بخوانی، مثل `List<?>`. تا وقتی لازم نشده خودت wildcard ننویس

پیام exception باید بگوید چه چیزی غلط بوده و مقدار غلط چه بوده. نوشتن فقط کلمه «خطا» کافی نیست.

**تمرین**

1. **خواندن امن عدد.** با `Scanner` یک `int` بخواه. اگر ورودی عدد نبود، `InputMismatchException` را بگیر، بنویس `لطفاً یک عدد صحیح وارد کن` و دوباره بپرس. حداکثر سه تلاش. `Scanner` را نبند. توکن غلط بعد از این exception هنوز داخل `Scanner` مانده؛ با `next()` دور بریز، وگرنه حلقه تمام نمی‌شود.
2. **سن معتبر.** متد `parseAge(String text)` اگر متن عدد نباشد یا سن منفی یا بیشتر از ۱۵۰ باشد، یک checked exception به نام `InvalidAgeException` پرتاب کند که در پیامش مقدار غلط را آورده باشد. `main` آن را `catch` کند و فقط همان پیام را چاپ کند، نه stack trace را.
3. **جعبه.** `Box<T>` با `put` و `get`. یک بار `Box<String>` و یک بار `Box<Integer>` بساز تا ببینی نوع را خود class تکراری نمی‌کنی.
4. **اولین عنصر.** متد `<T> T first(T[] items)` اولین عنصر را برگرداند. اگر آرایه `null` یا خالی بود، `IllegalArgumentException` با پیام روشن پرتاب کند.

**برای فاز بعد آماده‌ای وقتی** ورودی بد را به سقوط برنامه تبدیل نمی‌کنی، برای یک قانون مشخص exception مناسب پرتاب می‌کنی، و یک class ساده با `T` می‌نویسی.

## [فاز ۸ — Collections](core/08-collections.md)

**هدف:** به‌جای آرایه خام، بین List و Set و Map درست انتخاب کنی.

**موضوع‌ها**

- [ ] `List` و `ArrayList` وقتی ترتیب و تکرار مهم است
- [ ] `Set` و `HashSet` وقتی یکتا بودن مهم است
- [ ] `Map` و `HashMap` وقتی با کلید پیدا می‌کنی
- [ ] آشنایی با `TreeSet` و `TreeMap` فقط برای وقتی که ترتیب مرتب‌شده را می‌خواهی
- [ ] پیمایش با `for` و با `forEach`
- [ ] `equals` و `hashCode` با هم؛ اگر `equals` را نوشتی و `hashCode` را نه، `HashSet` درست کار نمی‌کند
- [ ] برای پیاده‌سازی از `Objects.equals` و `Objects.hash` استفاده کن
- [ ] `LinkedList` را برای این مسیر لازم نداری، مگر وسط یک لیست خیلی بزرگ مرتب حذف و اضافه کنی

قانون انتخاب:

- فهرست مرتب، تکرار مجاز: `ArrayList`
- عضو تکراری بی‌معنی است: `HashSet`
- جستجو با کلید: `HashMap`

**تمرین**

1. **دفترچه تلفن.** `HashMap<String, String>` از نام به شماره. افزودن، جستجو، حذف. اگر نام نبود بنویسد `چنین نامی نیست`، نه اینکه `null` خام چاپ کند.
2. **خرید.** اقلام را در `ArrayList` بگیر (حتی اگر تکراری وارد شد). یک فرمان چاپ، همه را نشان بدهد. یک فرمان دیگر فقط نام‌های یکتا را با `HashSet` چاپ کند.
3. **شمارش کلمه.** یک جمله را با `split(" ")` به کلمه بشکن و در `HashMap<String, Integer>` تعداد هر کلمه را بشمار. نتیجه را خط‌به‌خط چاپ کن.
4. **دانشجوی یکتا.** class `Student` با شماره دانشجویی، نام و `equals` / `hashCode` فقط بر اساس شماره. دو شیء با یک شماره و نام متفاوت بساز، هر دو را در `HashSet` بریز، و نشان بده اندازه مجموعه ۱ است.

**برای فاز بعد آماده‌ای وقتی** برای یک مسئله می‌گویی چرا `List` یا `Set` یا `Map`، و می‌توانی نشان بدهی `equals` بدون `hashCode` در `HashSet` غافلگیرت می‌کند.

## [فاز ۹ — Lambda و Stream](core/09-lambda-stream.md)

**هدف:** روی یک مجموعه، بدون حلقه طولانی، فیلتر و تبدیل و جمع‌بندی کنی.

**موضوع‌ها**

- [ ] lambda یعنی تابع کوتاه بدون نام: `n -> n >= 10`
- [ ] method reference مثل `System.out::println`
- [ ] `Stream` را از یک `List` با `.stream()` بگیر
- [ ] `filter`، `map`، `sorted`، `toList`
- [ ] `mapToInt` و `average` و `count`
- [ ] `Optional` برای «شاید نباشد»: `isPresent`، `orElse`، و چاپ پیام خودت به‌جای `NullPointerException`
- [ ] وسط `Stream` خود لیست منبع را عوض نکن

`Stream` جای `for` را همیشه نمی‌گیرد. برای یک پیمایش ساده، حلقه معمولی واضح‌تر است. Stream را وقتی زنجیره فیلتر و تبدیل داری به کار ببر.

**تمرین**

1. **نام‌ها.** یک `List<String>` از حداقل شش نام. با Stream آن‌هایی را که طولشان بیشتر از ۴ است نگه دار، مرتب کن، و با `System.out::println` چاپ کن.
2. **نمره و قبولی.** لیست حداقل شش `int`. با Stream میانگین را حساب کن و تعداد نمره‌های بزرگ‌تر یا مساوی ۱۰ را جداگانه چاپ کن. لیست خالی نباید استثناء عجیب بدهد؛ بنویس `نمره‌ای نیست`.
3. **جستجوی دانشجو.** از لیست `Student` فاز ۸، با Stream کسی را که شماره‌اش را می‌دهی پیدا کن و نتیجه را در `Optional` برگردان. اگر نبود دقیقاً چاپ کند `پیدا نشد`.
4. **تبدیل.** همان نام‌ها را با `map` به طول هر نام تبدیل کن و `toList()` را چاپ کن. کنارش همان کار را یک بار با `for` بنویس تا فرق خوانایی را خودت ببینی.

**برای فاز بعد آماده‌ای وقتی** یک لیست را با lambda فیلتر و map می‌کنی، نتیجه را با `toList` می‌گیری، و نبودن یک مقدار را با `Optional` به `NullPointerException` تبدیل نمی‌کنی.

## [فاز ۱۰ — فایل: I/O و NIO.2](core/10-io-nio2.md)

**هدف:** متن را در فایل بنویسی و بخوانی، و نبودن فایل را به‌شکل درست مدیریت کنی.

**موضوع‌ها**

- [ ] `Path` و `Path.of("notes.txt")`
- [ ] نوشتن و خواندن متن با `Files.writeString` و `Files.readString` (هر دو UTF-8 هستند، پس فارسی در فایل سالم می‌ماند)
- [ ] خواندن خط‌ها با `Files.readAllLines`
- [ ] try-with-resources وقتی منبع باید بسته شود
- [ ] `Files.list` برای دیدن محتوای یک پوشه؛ این Stream را هم باید ببندی
- [ ] فرق مسیر نسبی با مسیر از پوشه‌ای که برنامه را از آنجا اجرا کرده‌ای
- [ ] `IOException` یک checked exception است؛ یا آن را مدیریت کن یا در امضای `main` اعلام کن
- [ ] اگر فایل نبود، `NoSuchFileException` را بگیر و یک جمله فارسی چاپ کن

در این فاز سریال‌سازی بایتِ شیء (`ObjectOutputStream`) را یاد نمی‌گیریم. ذخیره را متنی و خوانا نگه دار.

**تمرین**

1. **یادداشت.** برنامه سه خط متن (یکی از خط‌ها نام امیررضا باشد) را در `notes.txt` بنویسد، بعد همان فایل را بخواند و عیناً چاپ کند.
2. **میانگین CSV.** یک فایل `scores.csv` بساز با این محتوا:

```text
ali,18
sara,15
reza,9
```

برنامه خط‌ها را بخواند، عدد بعد از ویرگول را جدا کند و میانگین را چاپ کند. یک خط خراب هم به فایل اضافه کن، مثل `nima,x`. اگر یک خط عدد نبود، همان خط را با شماره خط گزارش کند و بقیه را ادامه بدهد.

3. **فهرست txt.** با NIO.2 همه فایل‌های `.txt` پوشه جاری را چاپ کند. `Files.list` داخل try-with-resources باشد.
4. **فایل غایب.** همان برنامه میانگین را روی نام فایلی که وجود ندارد اجرا کن. خروجی باید یک خط باشد: `فایل پیدا نشد`. stack trace چاپ نشود.

**برای فاز بعد آماده‌ای وقتی** یک فایل متنی را با NIO.2 می‌نویسی و می‌خوانی، و اگر فایل نباشد برنامه با پیام روشن تمام می‌شود.

## [فاز ۱۱ — مبانی همزمانی](core/11-concurrency.md)

**هدف:** بدانی thread چیست، چرا وضعیت مشترک خطرناک است، و یک کار را به شکل مدرن Java 21 اجرا کنی.

این فاز مدل اجرا را یاد می‌دهد. ساخت سرور، سوکت، و وب در آن نیست.

**موضوع‌ها**

- [ ] thread یک مسیر اجرای جدا داخل همان برنامه است
- [ ] `Runnable` و `Thread.start`، نه صدا زدن مستقیم `run` اگر می‌خواهی واقعاً هم‌زمان شود
- [ ] `join` تا `main` قبل از تمام شدن کار، نتیجه را نخواند
- [ ] race: دو thread که یک متغیر را با `count++` عوض می‌کنند نتیجه را گم می‌کنند
- [ ] `synchronized` روی متد یا بلوک، برای محافظت از همان متغیر
- [ ] `ExecutorService`، `submit`، `Future.get`، و حتماً `shutdown`
- [ ] virtual thread در Java 21 با `Thread.ofVirtual().start(...)`
- [ ] virtual thread به‌صورت پیش‌فرض daemon است؛ اگر `main` زود تمام شود ممکن است پیامش را نبینی. `join` کن
- [ ] `wait` و `notify` را در این مسیر یاد نمی‌گیریم

**تمرین**

1. **شمارش گم‌شده.** یک فیلد `int count` و متد `add` که صدهزار بار `count++` کند. دو thread همان متد را روی یک شیء صدا بزنند. بعد از `join` هر دو، عدد را چاپ کن. انتظار خام ۲۰۰۰۰۰ است؛ چند بار اجرا کن و ببین اغلب کمتر است.
2. **شمارش درست.** همان برنامه را با `synchronized` طوری عوض کن که نتیجه همیشه `200000` باشد.
3. **دو کار، یک استخر.** با `Executors.newFixedThreadPool(2)` دو کار بفرست که هر کدام یک ضرب جدا را حساب کند و برگرداند. `main` هر دو `Future` را چاپ کند و در آخر `shutdown` کند.
4. **Virtual thread.** با `Thread.ofVirtual()` یک thread بساز که یک جمله را چاپ کند. `main` آن را `join` کند تا جمله حتماً قبل از پایان برنامه دیده شود.

**برای فاز بعد آماده‌ای وقتی** می‌توانی توضیح بدهی چرا دو thread روی یک `count++` نتیجه را کم می‌کنند، همان کار را با `synchronized` درست می‌کنی، و نتیجه یک `Future` را بعد از تمام شدن کار می‌خوانی.

## [فاز ۱۲ — JVM در حد یادگیرنده](core/12-jvm.md)

**هدف:** بدانی کد تو کجا به bytecode تبدیل می‌شود، stack و heap چه فرقی دارند، و classpath یعنی چه.

**موضوع‌ها**

- [ ] JDK شامل کامپایلر `javac`، فرمان `java`، و کتابخانه استاندارد است. همان را نصب می‌کنی
- [ ] `javac` متن را به bytecode در فایل `.class` تبدیل می‌کند
- [ ] JVM همان bytecode را اجرا می‌کند
- [ ] هر فراخوانی متد یک frame روی stack می‌سازد؛ متغیر محلی آنجاست
- [ ] شیء با `new` روی heap می‌نشیند
- [ ] garbage collector شیءی را که دیگر از هیچ جا به آن نرسی جمع می‌کند. در جاوا `free` نمی‌نویسی
- [ ] classpath یعنی JVM کلاس را کجا بگردد
- [ ] یک جمله درباره JIT کافی است: JVM بخش‌هایی را که زیاد اجرا می‌شوند به کد ماشین تبدیل می‌کند تا سریع‌تر شوند. تنظیم پرچم‌های JVM جزو این مسیر نیست
- [ ] از Java 9 ماژول هست. ما در این مسیر `module-info.java` نمی‌نویسیم؛ classpath برای همین برنامه‌ها کافی است

**تمرین**

1. **دیدن bytecode.** روی کلاس `Hello` این را بزن و در خروجی، نام `main` را پیدا کن:

```bash
javap -c -p Hello
```

لازم نیست دستورها را حفظ کنی. کافی است بگویی این متن، bytecode است نه کد منبع.

2. **فاکتوریل و stack.** متد بازگشتی `factorial(int n)` برای `n` بین ۰ و ۱۰. روی کاغذ فراخوانی‌های `factorial(4)` را تا رسیدن به ۱ بکش. هر فراخوانی یک frame با `n` خودش است. اگر `n` منفی بود `IllegalArgumentException` پرتاب کن.
3. **شیء روی heap.** در یک حلقه هزار `Book` بساز و نگه‌شان دار (مثلاً در یک `ArrayList`) تا قابل جمع شدن نباشند. در یک کامنت بالای حلقه به فارسی بنویس این شیءها کجا زندگی می‌کنند و چه کسی بعداً آزادشان می‌کند.
4. **مسیر کلاس.** `java Hello` را از یک پوشه دیگر اجرا کن تا خطای `could not find or load main class` را ببینی. بعد با درست کردن پوشه جاری، یا با گزینه `-cp`، همان برنامه را اجرا کن و یک خط بنویس که classpath را چه دادی.

**برای تمام شدن این مسیر آماده‌ای وقتی** فرق stack و heap را با یک متد و یک `new` از کد خودت توضیح می‌دهی، خروجی `javap` را bytecode می‌نامی، و خطای پیدا نشدن class را به مسیر اشتباه نسبت می‌دهی نه به «خراب شدن جاوا».

| بخش جلسه | زمان | کار |
| --- | --- | --- |
| مفهوم | ۱۰ تا ۲۰ دقیقه | همان موضوع فاز، با یک مثال کوتاه که خط‌به‌خط خوانده می‌شود |

قانون عبور از فاز: تمرین‌ها را خودت نوشته باشی، هر کدام یک بار واقعاً اجرا شده باشد، و جمله آمادگی همان فاز را بدون نگاه به جزوه نشان بدهی. تمام کردن فاز یعنی این، نه رد شدن از روی کد آماده.

اگر جلسه وسط یک تمرین تمام شد، جلسه بعد از همان تمرین ادامه بده. فاز جدید را وسط کار باز نکن.

## شروع از اینجا

جلسه بعد فقط **فاز ۱ — محیط و اولین برنامه** است. فاز ۲ را باز نکن.

سه کاری که همان جلسه با هم انجام می‌دهیم:

2. فایل `Hello.java` را با یک class و متد `main` می‌نویسیم، با `javac Hello.java` کامپایل می‌کنیم و با `java Hello` اجرا می‌کنیم.
3. همان برنامه را عوض می‌کنیم تا در دو خط، نام «امیررضا» و یک جمله کوتاه چاپ شود، و بالای `main` یک کامنت `//` بنویسیم که بگوید این برنامه چه می‌کند.
