# فاز ۱۱ — مبانی همزمانی

این درسنامه برای Java 21 است. thread یک مسیر اجرای جدا داخل همان برنامه است. این فاز مدل اجرا را یاد می‌دهد. ساخت سرور، سوکت، و وب در آن نیست. `wait` و `notify` را هم یاد نمی‌گیریم.

## چرا این‌طور کار می‌کند

یک برنامه به‌طور عادی از `main` یک مسیر را تا آخر می‌رود. `Thread` مسیر دوم را ممکن می‌کند. کار را در `Runnable` می‌گذاری، یعنی متدی به نام `run`. اگر خودت `run` را صدا بزنی، همان مسیر فعلی آن را اجرا می‌کند و همزمانی‌ای در کار نیست. `start` است که مسیر تازه را راه می‌اندازد.

`join` یعنی `main` همان‌جا بایستد تا آن thread تمام شود. بدون آن، `main` ممکن است نتیجه را قبل از نوشته‌شدنش بخواند، یا اصلاً برنامه را ببندد. virtual thread در Java 21 با `Thread.ofVirtual().start(...)` ساخته می‌شود. به‌صورت پیش‌فرض daemon است: اگر `main` تمام شود، JVM منتظرش نمی‌ماند. برای اینکه جمله‌اش را حتماً ببینی، `join` کن.

race این است: `count++` در واقع خواندن، جمع، و نوشتن است. دو thread می‌توانند هر دو مقدار ۱۰۰ را بخوانند، هر دو ۱۰۱ حساب کنند، و هر دو ۱۰۱ بنویسند. یک افزایش گم می‌شود. انتظار ۲۰۰۰۰۰ از دو بار صدهزار افزایش، تضمین زبان نیست. چند بار اجرا کن. اغلب کمتر است.

`synchronized` روی متد یا روی بلوک، برای همان شیء یک قفل می‌گذارد. thread دوم تا تمام شدن بلوک اول وارد همان قفل نمی‌شود. پس خواندن و نوشتن `count` وسط کار پاره نمی‌شود. قفل مال همان شیئی است که متد را روی آن صدا زده‌ای. دو thread باید یک شیء را شریک باشند تا این حفاظت کار کند. دو شیء، دو قفل جدا هستند.

`ExecutorService` ساختن thread را از فرستادن کار جدا می‌کند. `Executors.newFixedThreadPool(2)` دو thread را آماده نگه می‌دارد. `submit` کار را می‌فرستد و یک `Future` برمی‌گرداند. `Future.get` می‌ایستد تا نتیجه آماده شود و همان نتیجه را برمی‌گرداند. آخر کار `shutdown` را صدا بزن. بدون آن، استخر thread را زنده نگه می‌دارد و برنامه ممکن است تمام نشود.

## قاعده

برای همزمانی واقعی `start` کن، نه `run`. قبل از خواندن نتیجه `join` کن، یا روی `Future` متد `get` را بزن. وضعیت مشترک را با `synchronized` روی همان شیء ببند. استخر را `shutdown` کن. virtual thread را هم اگر باید خروجی‌اش را ببینی `join` کن.

## مثال

```java
synchronized void add() {
    count++;
}
```

بدون `synchronized`، دو thread که همین متد را روی یک شیء صدا بزنند افزایش را گم می‌کنند. با آن، هر افزایش تمام می‌شود و بعد نوبت بعدی شروع می‌شود.

```java
Thread worker = Thread.ofVirtual().start(() -> System.out.println("از نخ دیگر"));
worker.join();
```

`join` ممکن است `InterruptedException` بدهد. چون checked است، یا آن را می‌گیری یا در امضای `main` اعلام می‌کنی.

## اشتباه رایج

صدا زدن `run` به‌جای `start` و خیال کردن که کار موازی شده. هر دو فراخوانی پشت سر هم، روی همان thread اصلی، تمام می‌شوند. مسابقهٔ `count++` را این‌طور هرگز نمی‌بینی، چون اصلاً دو مسیر نداری.

## تمام است وقتی

بتوانی توضیح بدهی چرا دو thread روی یک `count++` نتیجه را کم می‌کنند، همان کار را با `synchronized` درست کنی، و نتیجهٔ یک `Future` را بعد از تمام شدن کار بخوانی.
