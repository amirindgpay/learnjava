# فاز ۱۲ — JVM در حد یادگیرنده

این درسنامه برای Java 21 است. سه جا را از هم جدا کن: متنی که می‌نویسی، bytecode که `javac` می‌سازد، و حافظه‌ای که موقع اجرا شیء و فراخوانی در آن زندگی می‌کنند. خطای پیدا نشدن class معمولاً مسیر است، نه خراب شدن جاوا.

## چرا این‌طور کار می‌کند

JDK سه چیز را با هم به تو می‌دهد: کامپایلر `javac`، فرمان `java`، و کتابخانهٔ استاندارد. همان را نصب می‌کنی. `javac` متن `.java` را به bytecode در فایل `.class` تبدیل می‌کند. JVM همان bytecode را اجرا می‌کند، نه متن منبع را. برای همین برنامهٔ کامپایل‌شده به منبع کنارش نیاز ندارد.

`javap -c -p Hello` bytecode متدها را نشان می‌دهد. لازم نیست دستورها را حفظ کنی. کافی است در آن خروجی نام `main` را پیدا کنی و بگویی این bytecode است، نه کد منبع.

هر فراخوانی متد یک frame روی stack می‌سازد. متغیر محلی و پارامتر همان‌جا هستند. فراخوانی بازگشتی `factorial(4)` چهار frame روی هم می‌گذارد، هر کدام با `n` خودش، تا برسد به پایه. برگشت، frame را برمی‌دارد. اگر `n` منفی باشد این زنجیره تمام نمی‌شود. قبل از فراخوانی دوباره، `IllegalArgumentException` پرتاب کن.

شیء با `new` روی heap می‌نشیند. متغیر محلی فقط ارجاع به آن شیء را در frame نگه می‌دارد. هزار `Book` که در یک `ArrayList` نگه‌شان داشته باشی هنوز از stack به heap می‌رسند، پس جمع نمی‌شوند. garbage collector شیئی را برمی‌دارد که دیگر از هیچ متغیر زنده‌ای به آن نرسی. در جاوا `free` نمی‌نویسی.

classpath یعنی JVM class را کجا بگردد. پیش‌فرض، پوشهٔ جاری است. `java Hello` از پوشه‌ای که `Hello.class` آنجا نیست، `could not find or load main class` می‌دهد. یا به همان پوشه برگرد، یا با `-cp` ریشهٔ جست‌وجو را بگو. این خطا یعنی «این نام را در این مسیر پیدا نکردم».

یک جمله دربارهٔ JIT کافی است: JVM بخش‌هایی را که زیاد اجرا می‌شوند به کد ماشین تبدیل می‌کند تا سریع‌تر شوند. تنظیم پرچم‌های JVM جزو این مسیر نیست.

از Java 9 ماژول هست. ما در این مسیر `module-info.java` نمی‌نویسیم. classpath برای همین برنامه‌ها کافی است.

## قاعده

متن، bytecode، و اجرای JVM را سه مرحله ببین. متغیر محلی را روی stack بگذار و شیء را روی heap. اگر class پیدا نشد، اول پوشهٔ اجرا و `-cp` را عوض کن. به نصب جاوا شک نکن تا وقتی `java -version` همان ۲۱ را نشان می‌دهد و فایل `.class` واقعاً جای دیگری است.

## مثال

```java
static int factorial(int n) {
    if (n < 0) {
        throw new IllegalArgumentException("n منفی است: " + n);
    }
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}
```

برای `factorial(4)` چهار frame با `n` برابر ۴، ۳، ۲ و ۱ روی هم می‌آیند. پایه برمی‌گردد و هر frame حاصل را در frame بالایی ضرب می‌کند.

```bash
javap -c -p Hello
java -cp . Hello
```

فرمان دوم می‌گوید classpath همین پوشه است. اگر `.class` آنجا باشد، همان برنامه‌ای است که بدون `-cp` از داخل همان پوشه اجرا می‌کردی.

## اشتباه رایج

دیدن `could not find or load main class Hello` و نتیجه‌گرفتن که جاوا خراب شده. class هست. JVM در پوشه‌ای که الان در آن ایستاده‌ای دنبالش می‌گردد و پیدا نمی‌کند.

## تمام است وقتی

فرق stack و heap را با یک متد و یک `new` از کد خودت توضیح بدهی، خروجی `javap` را bytecode بنامی، و خطای پیدا نشدن class را به مسیر اشتباه نسبت بدهی نه به «خراب شدن جاوا».
