# فاز ۸ — Collections

این درسنامه برای Java 21 است. آرایه طولش ثابت است و خودش نمی‌داند عضو تکراری یعنی چه، یا کلید چیست. `List` و `Set` و `Map` این سه نیاز را از هم جدا می‌کنند.

## چرا این‌طور کار می‌کند

`List` ترتیب را نگه می‌دارد و تکرار را مجاز می‌کند. `ArrayList` پیاده‌سازی معمولی آن است: افزودن به ته ارزان است و خواندن با اندیس مستقیم است. این همان فهرست خرید است، حتی اگر یک کالا را دو بار گفته باشی.

`Set` عضویت را بدون تکرار نگه می‌دارد. `HashSet` این کار را با `hashCode` و بعد `equals` می‌کند. اگر دو شیء با `equals` برابر باشند و `hashCode` یکی ندهند، مجموعه هر دو را نگه می‌دارد و یکتایی دروغ می‌شود. `TreeSet` به‌جای این، اعضا را مرتب نگه می‌دارد. فقط وقتی ترتیب مرتب‌شده را می‌خواهی سراغش برو. `TreeMap` همین نقش را برای کلید دارد.

`Map` مقدار را با کلید پیدا می‌کند، نه با اندیس. `HashMap<String, String>` برای نام به شماره کافی است. `get` اگر کلید نباشد `null` برمی‌گرداند. آن `null` را خام چاپ نکن. اول بپرس کلید هست یا نه، و اگر نیست جملهٔ خودت را بنویس.

پیمایش با `for` روی `List` و `Set` همان شکلی است که برای آرایه دیدی. `forEach` یک کار کوچک را روی هر عضو انجام می‌دهد. برای `Map`، روی `entrySet` برو تا هم کلید را داشته باشی هم مقدار را.

اگر `equals` را خودت می‌نویسی، `hashCode` را هم با همان فیلدها بنویس. `Objects.equals` دو مقدار را مقایسه می‌کند و با `null` نمی‌ترکد. `Objects.hash` از همان فیلدها یک `hashCode` می‌سازد. برای دانشجو، اگر هویت همان شمارهٔ دانشجویی است، هر دو متد فقط همان شماره را ببینند. نام در برابری نباشد، وگرنه دو شیء با یک شماره و دو نام، در مجموعه دو عضو می‌شوند.

`LinkedList` را برای این مسیر لازم نداری. فقط وقتی وسط یک فهرست خیلی بزرگ، زیاد حذف و اضافه می‌کنی، فرق عملی‌اش دیده می‌شود. پیش‌فرض `ArrayList` است.

## قاعده

فهرست مرتب با تکرار مجاز: `ArrayList`. تکرار بی‌معنی است: `HashSet`. پیدا کردن با کلید: `HashMap`. ترتیب مرتب‌شده خواستی: `TreeSet` یا `TreeMap`. هر وقت `equals` را نوشتی، `hashCode` را با همان فیلدها بنویس.

## مثال

```java
Map<String, String> phoneBook = new HashMap<>();
phoneBook.put("آرمین", "0912");
String number = phoneBook.get("آرمین");
if (number == null) {
    System.out.println("چنین نامی نیست");
}
```

```java
@Override
public int hashCode() {
    return Objects.hash(id);
}

@Override
public boolean equals(Object other) {
    return other instanceof Student s && Objects.equals(id, s.id);
}
```

اگر `hashCode` را برنداری و به نسخهٔ `Object` بسپاری، این `equals` در `HashSet` دیده نمی‌شود.

## اشتباه رایج

نوشتن `equals` بر اساس شمارهٔ دانشجویی و رها کردن `hashCode`. دو شیء با یک شماره در `HashSet` دو عضو می‌مانند، چون اول به دو سطل متفاوت می‌روند و نوبت به `equals` نمی‌رسد.

## تمام است وقتی

برای یک مسئله بگویی چرا `List` یا `Set` یا `Map`، و بتوانی نشان بدهی `equals` بدون `hashCode` در `HashSet` غافلگیرت می‌کند.
