# فاز ۷ — Exception و Generics

این درسنامه برای Java 21 است. exception جریان عادی را قطع می‌کند و یک شیء خطا به بالا می‌فرستد. generic یک class یا متد را نسبت به نوع باز می‌گذارد، بدون اینکه برای هر نوع یک کپی بنویسی.

## چرا این‌طور کار می‌کند

وقتی `throw` می‌کنی، جاوا بقیهٔ همان مسیر را اجرا نمی‌کند. دنبال یک `catch` می‌گردد که نوع خطا را بشناسد. اگر پیدا نکند، نخ همان‌جا می‌میرد و stack trace چاپ می‌شود. `try` محدوده‌ای است که این اتفاق ممکن است بیفتد. `finally` بعد از آن اجرا می‌شود، چه خطا آمده باشد چه نه.

unchecked یعنی زیر `RuntimeException`. `IllegalArgumentException` و `InputMismatchException` از این دسته‌اند. مجبور نیستی در امضا اعلامشان کنی، ولی اگر ورودی بد را نگیری برنامه می‌خوابد. checked زیر `Exception` است و زیر `RuntimeException` نیست. یا `catch` می‌شود یا در امضا با `throws` اعلام می‌شود. `throw` خود پرتاب است. `throws` فقط به صدازننده خبر می‌دهد.

پیام باید بگوید چه چیزی غلط بوده و مقدار غلط چه بوده. کلمهٔ «خطا» به‌تنهایی به درد نمی‌خورد. exception اختصاصی تو، مثلاً برای سن، یک class است که `Exception` را `extends` می‌کند تا checked باشد. پیام را در سازنده به `super` بده.

try-with-resources را اینجا فقط بشناس: منبعی که باید بسته شود را در پرانتز `try` می‌گذاری و جاوا آخرش می‌بندد. بستن فایل مال فاز ۱۰ است. `Scanner` وصل به `System.in` را نبند. `close` آن، ورودی استاندارد را هم می‌بندد. یک نکتهٔ خود `Scanner`: بعد از `InputMismatchException` توکن غلط هنوز داخلش مانده. اگر با `next()` دور نریزی، دور بعدی حلقه همان توکن را دوباره می‌بیند و تمام نمی‌شود.

`Box<T>` یک class است که نوع محتویاتش را موقع استفاده انتخاب می‌کنی. `Box<String>` و `Box<Integer>` دو بار نوشتن class نیست. کامپایلر همان class را با نوع همان استفاده چک می‌کند، تا رشته را در جعبهٔ عدد نگذاری. متد generic هم همین کار را برای یک متد می‌کند: `<T> T first(T[] items)`.

`T extends Number` یعنی هر نوعی که بگذاری باید `Number` یا فرزندش باشد. داخل متد می‌توانی با آن مثل عدد رفتار کنی. علامت `?`، مثل `List<?>`، یعنی «لیستی از یک نوع ناشناس». اینجا فقط باید بتوانی این امضا را بخوانی. تا وقتی لازم نشده خودت wildcard ننویس.

## قاعده

ورودی بد را به سقوط برنامه تبدیل نکن. برای قانون مشخص، exception با پیامِ شامل مقدار غلط پرتاب کن. checked را یا بگیر یا اعلام کن. `Scanner` روی `System.in` را باز بگذار. generic را وقتی بنویس که بدنه برای چند نوع یکی است و نوع را صدازننده انتخاب می‌کند.

## مثال

```java
class InvalidAgeException extends Exception {
    InvalidAgeException(String text) {
        super("سن نامعتبر: " + text);
    }
}
```

`main` این را `catch` می‌کند و `getMessage()` را چاپ می‌کند، نه خود exception را. چاپ خود exception، stack trace را هم می‌آورد.

```java
class Box<T> {
    private T value;

    void put(T value) {
        this.value = value;
    }

    T get() {
        return value;
    }
}
```

یک بار `Box<String>` و یک بار `Box<Integer>` کافی است تا ببینی class را تکرار نکرده‌ای.

## اشتباه رایج

`catch (InputMismatchException e)` بدون دور ریختن توکن غلط. حلقهٔ «دوباره بپرس» همان ورودی بد را بی‌نهایت می‌خواند، چون `Scanner` هنوز روی آن ایستاده.

## تمام است وقتی

ورودی بد را به سقوط برنامه تبدیل نکنی، برای یک قانون مشخص exception مناسب پرتاب کنی، و یک class ساده با `T` بنویسی.
