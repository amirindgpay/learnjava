# پاسخ فاز ۷ — Concurrency و Java Memory Model

## ۱

atomicity نه. visibility نوشتنِ خود متغیر بله. `count++` سه قدم است و `volatile` آن را یک قدم نمی‌کند.

## ۲

بله، اگر آن نوشتن‌ها در همان نخ قبل از نوشتن `volatile` بوده باشند. رابطه happens-before است: نوشتن `volatile` قبل از خواندن بعدی همان متغیر.

## ۳

به carrier pin می‌شود و تا پایان بلوکه همان نخ پلتفرم را نگه می‌دارد. `ReentrantLock` در Java 21 این pin را ندارد.

## ۴

در Java 21 هنوز preview است. بدون `--enable-preview` در API پایدار ۲۱ نیست و حتی با آن هم شکل API را پایدار فرض نکن.

## ۵

`shutdown` کار تازه نمی‌پذیرد و پذیرفته‌شده را تمام می‌کند. `shutdownNow` تلاش می‌کند در حال اجرا را interrupt کند و صف شروع‌نشده را برمی‌گرداند.

## ۶

deadlock استخر. جا برای taskی که باید قفل انتظار را باز کند نمانده، چون هر دو نخ خودشان منتظر همان استخرند.

## ۷

deadlock. هر نخ مانیتوری را گرفته که دیگری برای وارد شدن به آن ایستاده.
