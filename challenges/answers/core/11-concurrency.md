# پاسخ فاز ۱۱ — مبانی همزمانی

## ۱

نه. `run` کار را روی همین thread اجرا می‌کند. برای مسیر جدا `start` لازم است.

## ۲

نه. `count++` خواندن و نوشتن جداست و دو thread می‌توانند یک افزایش را گم کنند. عدد اغلب کمتر از ۲۰۰۰۰۰ است.

## ۳

نه. قفل `synchronized` روی متد نمونه، قفل همان شیء است. دو شیء دو قفل دارند.

## ۴

virtual thread پیش‌فرض daemon است. اگر `main` زود تمام شود JVM منتظرش نمی‌ماند و جمله ممکن است چاپ نشود. `join` این را می‌بندد.

## ۵

زنده بماند. نخ‌های استخر تمام شدن `main` را به‌تنهایی دلیل خروج نمی‌دانند تا `shutdown` شود.

## ۶

منتظر می‌ماند. خطای خود کار را در `ExecutionException` می‌بینی، نه به‌صورت خام.

## ۷

```java
synchronized void add() {
    count++;
}
```

هر دو thread باید این متد را روی یک شیء صدا بزنند.
